# ms-11 — the phone rings: a real number answered by the platform

**Landed 2026-08-31 · 4 cards (3 by the orchestrator, 1 by an Opus worker) · lands on master with this milestone**

## What we set out to do

Make a telephone ring into the fleet. A dedicated box in GCP running the SFU
and the SIP bridge, a Twilio elastic trunk pointing at it, a real number from
the account we already pay for, and the routing thesis under PSTN conditions:
the number the caller dialled is a *route* in a table, never a project in
code. The human's mobile is the acceptance test.

## What we achieved

- **`convo-box`** (e2-standard-4, dedicated, created live with the human):
  livekit-server + livekit-sip + redis in docker with host networking,
  real keypair generated on the box and never in git, firewall for
  SIP/RTP/WebRTC, `lk.bernardocastro.dev` in Route 53.
  `./infra/box/setup.sh` is the whole deploy, idempotent, from the laptop.
- **+1 417 674 3169 answers as Clínica Norte.** A free number already on the
  pinecall Twilio account (nothing bought), attached to a new elastic trunk
  whose origination is `sip:lk.bernardocastro.dev`. LiveKit side: an inbound
  trunk restricted to Twilio's signalling CIDRs (with `hide_inbound_port`
  dropping everything else) and a dispatch rule that names **no tenant** —
  `store.route(fleet, number)` decides, and
  `python -m convo routes add` is how a number changes hands. No deploy.
- **The human called from his mobile** (session `AJ_8f4aEo9wHsKj`): three
  voice turns with the receptionist, the full `sip.*` map on `session.start`
  (his number, Twilio's callSid, trunk and rule ids), consent DAG **1.0** and
  grounding **1.0** on the replayed session, €0.0098 the call.
- **The path was proven before the human dialled**: Twilio refuses
  account-to-self calls (error 21216), so `scripts/sip_probe.py` sends the
  exact INVITE Twilio sends — 200 OK, room created, agent dispatched, tenant
  routed by number, twice, for €0.02.

## What we learned the hard way

1. **A phone call is a *room* job, not a participant job.** The dispatch rule
   asks for the agent when the room is created, so `ctx.job.participant` is
   empty and `sip.trunkPhoneNumber` lives on the SIP participant *inside* the
   room. The router read it off the job: every real call would have answered
   as the env-default tenant, on the **chat** channel — a silent phone. The
   framework itself confirms the shape (`worker_type: JT_ROOM`). `core/sip.py`
   finds the caller in the room with a bounded wait that returns immediately
   in the common case, and skips entirely when `TENANT` is set (a console has
   nobody to wait for).
2. **Latency has an anatomy, and the log wrote it down.** Greeting 3.2s;
   turns e2e 2.5–2.7s = end-of-turn 0.3–2.5s + LLM ttft 1.6–1.9s + TTS. The
   audio path today is absurd on purpose: phone → Twilio → box (Iowa) →
   **worker on a laptop in Spain** → STT/TTS/LLM in the US. Two Atlantic
   crossings per frame and ~120ms extra on every provider round trip. Moving
   the worker to the box (ms-10) recovers ~0.5–0.8s/turn; Haiku's ~1.4s ttft
   is the floor any stack pays; `eleven_flash_v2_5` (~75ms vs ~400ms ttfb)
   is a project flag we already support. One turn hit the 2.5s max-endpoint
   delay on an ambiguous question — semantic endpointing working as tuned,
   tunable further.
3. **`livekit/sip` versioning bites twice**: there are no `v0.x` tags on
   Docker Hub (v1.12 is current), and v1.12 ignores `SIP_CONFIG_FILE` — it
   reads `/sip/config.yaml`, so that is where the config mounts.
4. **Credentials rot silently.** The `TWILIO_API_KEY` in
   `~/pinecall/sdk-server/.env.production` and all four twilio-cli profiles
   are revoked (401/20003); the working pair was in `playground/.env`. A
   rotation is pending on the pinecall side.
5. **A test that decodes tokens must read the real secret.** The seam card's
   token tests used the literal `"secret"`; the moment the box's keypair
   landed in `.env` they went red. They read the environment now.

## Decisions

- **A dedicated box, not the shared one.** `pinecallgpu` turned out to be
  2 vCPU with live services and another user; the human chose a clean
  e2-standard-4 that dies with the project. Docker came back with it.
- **The worker stays on the laptop until ms-10.** Workers dial *out* to the
  SFU, so nothing needs exposing to run one anywhere — that asymmetry is
  what let the phone ring today with zero deploy tooling.
- **Transfers (REFER / WarmTransferTask) wait for ms-15**: a warm transfer
  needs somewhere to transfer *to*, and that story belongs with the
  supervisor UI.
- **The number is data end to end**: Twilio → trunk → inbound trunk →
  dispatch rule (tenant-less) → routes table. Onboarding a customer's number
  is one API call and one route row.

## Where we stand

The platform now does the thing it was designed for: **a stranger can dial a
phone number and a business answers**, with the audit trail, the consent
token, the cost line and the eval all attached to that real call. The line is
live while the laptop worker runs. Latency is measured and its fixes are
scheduled, not guessed.
