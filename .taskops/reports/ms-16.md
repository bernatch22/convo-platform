# ms-16 — the deck: fifteen slides, six writers, one editor with the human live

The milestone that had to produce the thing ABAI actually asked for: a technical
design covering thirteen *entregables*, in at most fifteen slides, with an
architecture diagram and a sequence diagram. We shipped fourteen slides, a
self-contained `deck.html`, a 14-page PDF and — because the exercise accepts a
document *or* slides, and having both is strength — an 8-to-12-page `REPORT.md`
that says the same things in prose.

The interesting part is not the deck. It is that five agents wrote it in
parallel, in a language none of them shares by default, and a cold reader cannot
find the seams.

## What we set out to do

One card per slide group, five groups, dispatched at once, plus a sixth card —
this one — to assemble. The risk was obvious from the plan: five writers on one
artefact produces five voices, five vocabularies and five sets of numbers about
the same platform. Nothing about parallelism prevents that; the plan has to.

## What we achieved

- `presentation/MANIFEST.md` — the writing contract, landed **before** any
  fragment. It fixes each slide's number, title, entregable, what has to be on
  it, what carries its evidence, and the CSS class kit a writer may use.
- Fourteen fragments in `presentation/slides/NN-name.html`, each a bare
  `<section class="slide">`, one file per writer, so two writers' work never met
  in a diff.
- `build.mjs` / `serve.mjs` / `audit.mjs` / `pdf.mjs` / `deck.js` — ~400 lines,
  no dependencies: fragments in, one self-contained HTML file and a PDF out,
  driven by whatever Chromium is already on the machine.
- `dist/deck.html` (710 KB, opens from a USB stick) and `dist/deck.pdf`
  (1.3 MB, exactly 14 pages of 1600×900).
- `REPORT.md`, 13 sections plus two appendices, in Spanish, with the same
  numbers as the deck and an evidence index that names a command or a test for
  every claim.

## What we learned the hard way

**A fixed-size page needs a gate, because the browser will not give you one.**
A slide taller than 900px is not warned about anywhere: it is cropped on screen
and becomes a silent fifteenth page in the PDF. `audit.mjs` measures every slide
in headless Chromium and reports through `document.title` — the one value
`chrome --headless --dump-dom` hands back without a devtools client. During the
coherence pass alone it caught four overflows, on slides 03, 12 and 14 (twice),
and **every one of them came from adding two lines of prose to a slide that
already fit**. On a fixed page, editing is trading, not adding. The gate turned
that from a lesson into a loop: change, measure, cut, measure.

**The manifest fixed what each slide says; it could not fix when each writer
looked.** Slide 03 arrived saying the supervisor had a signed ticket and
listening but "neither whisper nor takeover". Slide 10, written by a different
agent in the same hour, showed all three capabilities with sixteen tests behind
them. Both fragments were true when they were written — the writers had branched
from different points, and ms-15 had landed in between. The real cause is not
carelessness; it is that a worktree is a photograph. The cheap fix for next time
is a manifest rule we did not have: **a proof line should name the commit, the
doc section or the test file it was read from, not only the command that would
re-run it**. A dated claim can be checked against the calendar; an undated one
can only be checked by rebuilding it.

The same root cause produced a spread of stale numbers that the assembly pass
had to reconcile against one source each:

| claim | as written | as shipped | source of truth |
|---|---|---|---|
| clinic goldens in the model matrix | 12 | 17 | `docs/evals.md §10`, ms-18 re-run |
| ring-4 judge cost | 0,0018 € | 0,0014 € | `docs/evals.md §3.13`, measured twice |
| modules in `core/` | 60 | 108 | `git ls-tree` on the trunk |
| milestones closed | 10 of 16 | 18 of 20 | `.taskops/reports/README.md` |
| per-call LLM cost on the infra slide | ≈ 0,01 € | 0,0017–0,0106 € | the six real sessions on slide 12 |

None of those was a lie when it was typed. All five were lies by the time the
deck assembled. **A deck written in parallel does not need a proofreader; it
needs a reconciler**, and that is a different job: not "is this sentence good"
but "is this the same platform as the sentence on the other slide".

**A style example will be copied verbatim.** The manifest illustrated the voice
with a real sentence — *"El consentimiento es un paso de la saga, no una frase
del prompt"* — and it came back as slide 06's headline **and**, nearly word for
word, inside slide 01's opening paragraph, along with the image that follows it
("cuando el modelo se salta la instrucción no hay excepción, hay una cita que
nadie pidió"). Two slides making the same argument in the same words is the one
seam a reader feels immediately, because it reads like a person who forgot they
had already said it. Next time the manifest's examples get marked *do not reuse
verbatim* — or, better, are written about a subject the deck does not cover.

**Terminology drifts in the small words, not the big ones.** Nobody wrote
"herramienta" instead of "tool" — the code's vocabulary held. What drifted was
`registro`, used for the tenant *registry* on slides 08 and 09 and for the event
*log* on slide 10; and `irrutable`, a word that does not exist, next to `no
enrutable`, which does. Small enough to survive review, loud enough to make a
careful reader stop.

## Decisions

- **Refresh the model matrix rather than date it.** The reviewer offered both:
  update slide 12's table to the ms-18 two-model run, or label the old one
  loudly. The deck ships from the trunk, where ms-18 has landed, so a dated old
  table would have been an artefact explaining itself. Refreshed, with the
  divergence count recomputed (five over 28 goldens, from eight over 23) and the
  proof line naming `docs/evals.md §10` for the golden-by-golden detail.
- **`REPORT.md` in Spanish.** The skeleton was English headings with a Spanish
  summary appendix. The deck is Spanish and so is the reader. A document whose
  body and appendix are in different languages reads as a translation of itself.
- **`REPORT.md` written *from* the assembled deck, not beside it.** That is the
  only reason the numbers agree: the reconciliation happened once, in the
  fragments, and the prose inherited it.
- **The narrator stays parked.** `presentation/stage/` — the `@pinecall/stage`
  voice runtime — is out of the critical path by decision: the deliverable is a
  document and a walkthrough, and a narrator in the critical path makes both
  hostage to a network. Narrating this deck is still a card; it is not this one.

## The second act — the human took the red pen

Everything above produced a deck that was *correct*. What it was not yet was
*good*, and the difference took a full second pass, page by page, with the human
reading every render and answering in real time. The lessons of that pass are
the ones worth keeping:

**A deck is reviewed by rendering, never by reading.** The audit gate catches
overflow; it cannot catch a washed-out grey footnote, a squeezed column or a
slide that "fits" and still reads like a manual. Every page of the final deck
was rendered to PNG and *looked at* before being shown — and slide 1 still took
three full iterations, the last one from a deleted file, because the human's
eye kept finding what the gate could not. The workflow that survived: edit →
build → audit → pdf → render one page → look → repeat.

**The live platform kept correcting the deck.** Writing the concurrency slide
forced a real probe against production — which found `mint_caller` handing out
loopback URLs, the fourth and last token mint with that bug. Rehearsing the
ticket flow for the demo found the handoff dropping the customer's complaint
and a few-shot example dictating another customer's ticket number. Each time,
the sentence on the slide got cheaper to defend because the thing it described
got fixed first. The shield sentence on slide 1 — the live system is the
verification, not the deliverable — turned out to be operationally true.

**An external review is a free red team.** A 9.2/10 review's three complaints
were all actionable: the persistence trade-off got its missing sentence (the
storage contract does not depend on the local engine — true in the code, every
job writes through the control plane), LiveKit's rivals got named (Vapi is a
panel over somebody else's loop; Pipecat brings the pipeline but no SFU, no
SIP, no multi-user supervision), and the EU AI Act got a strip on slide 14:
limited risk, art. 50 transparency — which we then *implemented* (both
greetings now open with «asistente virtual», e71eaea) so the deck describes
the deploy, not an intention.

**Methodology is content, not a footnote.** The final slide 1 gives «cómo se
construyó» a first-class card: incremental milestones, Claude Code agents in
parallel on isolated git worktrees, the human in the loop approving every
close — and the public board as evidence. The narrated-deck card was dropped
for the same reason in reverse: a talking deck is a demo of a demo; the test
is read, not performed.

**Where a demo page lives is an architecture question.** `/demo.html` sits in
`ui/public/` because Vite copies `public/` into `dist/` on every deploy and
`core/webui.py` serves real files before the SPA fallback — no Caddy change,
versioned in git, survives redeploys. The first copy was hand-dropped into the
box's `dist/` so the URL worked the same night; the committed one replaces it
on every build.

## Where we stand

Fifteen slides, every one visually verified, all thirteen *entregables*
covered, the two required diagrams in, the 900px audit green on all fifteen,
`dist/deck.pdf` at exactly 15 pages of 1600×900 and a copy always current on
the desktop. Slide 1 carries the live URL, the phone number, the marked
«Ver demo /demo.html» pill and the public board link.
