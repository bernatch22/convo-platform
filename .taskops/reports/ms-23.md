# ms-23 — the refactor: one package with a Rails shape, prose out of the code, an open-source README

**Landed 2026-09-03 · 1 card, done by the orchestrator in-session · lands on master with this milestone**

## What we set out to do

Twenty-two milestones had grown the repository by accretion and it showed: four
Python entry points at the root, a `core/` whose `testing/` was a third of it,
two byte-identical copies of `stage_prompt()`, three copies of the Spanish
month names, prompts as Python string constants, 7,747 lines of docstring
essays over 11,601 lines of code, a `presentation/` nothing ran, and a README
that read as a lab notebook. Reshape it into ONE installable package with the
layout Rails gives an app, keep every behaviour, and make the code read in one
line per symbol.

## What we achieved

- **One package.** `core/`, `api.py`, `worker.py` and the CLI live under
  `convo/`, grouped by responsibility: `domain/` (contracts, no framework),
  `agents/`, `prompting/`, `tools/`, `session/`, `providers/`, `state/`,
  `telephony/`, `supervision/`, `scoring/`, `observability/`, `lang/`, `api/`,
  `evals/`, `testing/`. `pyproject.toml` builds it with hatchling and exposes
  `convo` as a console script: `uv run convo console --text`.
- **Prompts are views.** Each stage's prompt is `prompts/<stage>.md`; shared
  paragraphs are `prompts/_partials/*.md` partials included by name; the four
  confirmation prompts are `prompts/<stage>/confirm.md`; the knowledge sheet is
  `prompts/knowledge.md`. One layout, `convo/prompting/layout.py`, renders all of them
  for every tenant. **Every rendered prompt is byte-identical to master** (diffed
  over both tenants, every stage and every confirmation prompt).
- **One Spanish calendar.** `convo/lang/es.py` replaces the clinic's
  `dates.py`, the shop's `dates.py` and the month table inside the clock note.
- **The API is one router per resource.** 908 lines become nine modules under
  `convo/api/`; `app.py` is the lifespan and the include list.
- **Prose left the code.** 5,510 docstring lines from 162 modules moved to
  `docs/decisions/<module>.md` (indexed); every docstring is now one line. Tool
  docstrings (the model's schema) and route docstrings (the client's JSON
  shapes) were kept whole. Prose over code: 0.73 → 0.28.
- **No file over 400 lines.** The six long test modules were split by their own
  section headers, with shared fakes in `tests/fixtures/`.
- **`presentation/` is gone** (its fábrica had no runtime dependents);
  `docs/deck.pdf` keeps the deliverable. Scripts moved to `infra/scripts/` with
  argparse fronts; the seeded phone number moved to `infra/seed/routes.json`.
- **README and CLAUDE.md rewritten** for the layout that exists.

Numbers: 790 unit tests green (789 on master; `test_prompts` gained one
parametrisation), ruff clean, the API answers `/tenants`, the console opens.

## What we learned the hard way

1. **A rewrite of imports needs a rewrite of ROOT imports too.** `from core
   import confirm` was a shape my first pass did not see, and `from
   convo.testing import matrix` broke the instant `matrix` moved into a
   subpackage. Per-name mapping, not per-module, is the rule for packages that
   re-export.
2. **ruff `--fix` removes what you have not yet used.** Adding an import and
   replacing its uses in two separate steps lets the formatter delete the import
   in between. Replace first, import second, or do both in one edit.
3. **ruff format re-joins docstrings.** A two-line docstring written to stay
   under 100 columns comes back as one line over the limit. Shorten the words,
   not the layout.
4. **Imported fixtures shadow their parameters** (F811). A fixture imported from
   `tests/fixtures/` and then asked for by name in a test signature is flagged;
   `per-file-ignores` on `tests/*` is the honest fix, not a rename.
5. **The board's MCP server reads its credential once.** After the invite was
   renewed on disk the session's server kept answering "expired" until it was
   reconnected from the host. The join is not the fix; the reconnect is.

## Decisions

- **Stages stay.** The word is this project's, not LiveKit's; a stage is one
  `Agent` with its own prompt and tools, and it maps cleanly onto a controller.
- **Partials include by name, with a `{% include %}` line and nothing else.**
  No template engine: a regex, a file, and the test that pins the composition.
- **`messages.py` / `helpers.py`** split a project's `tools.py` by what the
  model reads versus what the code computes; `tools` was the wrong word for a
  module that held no tool.
- **`settings.py` holds the deploy knobs that were code** (default tenant and
  project, the fleet name, the seed file). The 50-odd provider-key reads stay
  where they are; centralising them is a later card and would have moved
  behaviour, which this milestone forbade.
