# ms-14 — the console: one UI, distrusted, audited, and finished

**What we set out to do.** The full console on top of the tested core: tenant/
project switcher, conversation (voice/chat/phone) with live transcript, call
log, sessions with latencies, pipeline controls — and, added mid-chapter by
the human's call, evals **visible and runnable** from the screen instead of
deferred to the presentation chapter.

**Where it stands.** All of it works against the box. The rail switches
tenants and projects by URL alone; a conversation screen serves three doors
(voice, chat, observe) through one hook; Sessions shows each call's event log
with per-turn latencies; Pipeline changes voice, TTS model, STT provider, LLM
model and greeting with no deploy; Evals lists every DeepEval run with a
per-metric diff against the previous one and launches new runs with a button.

## The audit — because the human said "desconfío"

Most of this chapter was built by Opus workers; the human asked for a full
re-review by a different pair of eyes. The audit read every stream, timer and
effect: **all clean** — polling components use an `alive` flag plus
`clearInterval`, `useTimeline` returns the SSE unsubscribe as its effect
cleanup, `useRoom.close()` removes the audio elements it appended and
disconnects the Room, and the EventSource closes itself on the server's `end`
frame. Zero hardcoded colors outside `tokens.css`, zero `any`, zero
`console.log`, zero `@ts-ignore`. Two subtleties worth stealing: the client
distinguishes EventSource's own `open` event from the server's `open` frame by
whether it carries data, and speakers are identified by participant identity,
never track id (chat mode has no tracks).

## The voice bug — the real cause, reproduced before fixed

The human picked Carolina and heard someone else; suspicion fell on the
picker. The picker was innocent. The reproduction (one curl): `PUT
{"voice": ""}` answered **200** — `overridable()` had rules for models and
providers and none for `voice`. The runtime then absorbs an empty voice as
"no TTS configured" (`tts_for` cannot tell it from a missing API key), so the
next voice call came up **mute** while the log blamed `ELEVENLABS_API_KEY`.
The free-text "another voice id…" option mounted empty and stored that empty
string on save.

The fix is layered: blank refused at the door, values stripped before
judgment, `overrides.apply` ignores an already-stored blank for every field
but greeting, and — the part that makes the next such bug answerable —
`session.start` now records the pipeline the session actually built (voice,
tts_model, stt_provider, llm_model). The bug was unanswerable from the log;
now the log answers first.

## The incident the chapter caught live

With the LLM a console-switchable slot, somebody stored `gpt-5.4-mini` — legal
per the allow-list — on a box that had no `OPENAI_API_KEY`. Every job of that
project crashed with a `KeyError` for hours: **a legal config took a project
off the air.** The guard now has two layers: the door (api.py runs on the box,
so `overridable()` refuses an override whose vendor key is absent, naming the
exact variable) and the net (provider factories treat a missing key as
garbage-config and fall back to the default with one warning line — a stored
override can never again kill a fleet). The pipeline view carries
`unavailable_reasons` so the console can grey out a choice before anyone
picks it.

## Evals on screen — the decisions that make it trustworthy

Scores are read from deepeval's **own** `test_run_*.json`, so the screen and
the CLI cannot disagree. Suites are tenant data (`evals/suites.json` per
project) read off disk — core still imports no tenant. The runner is capped:
one run at a time (a second POST is a 409, never a queue), hard 15-minute
SIGKILL, log tee'd and tailed live in the UI. Each metric ships with its delta
against the previous scored run of the same suite, matched by start time so a
late CI filing never diffs against the future.

## Also in this chapter

- **Light theme**: one token layer (`:root[data-theme="light"]` redefines
  tokens only), pre-paint inline script so no flash, accent `#5f7d16` at
  AA contrast. No component owns a hex in either theme.
- **One domain**: the console is served by the same Caddy that fronts the SFU
  (`/rtc*`/`/twirp*`/WS-upgrade → livekit, everything else → api.py), so the
  public UI writes the very store the phone worker reads — dev and prod are
  the same seam.

## What a stranger could reuse

The Rail's URL-as-state pattern (navigation is the only state manager), the
EventSource open-vs-open disambiguation, the `alive`-flag polling idiom, the
runs-store-reads-deepeval's-own-JSON trick, and `unavailable_reasons` as the
general shape for "legal but not runnable here".

**Honest gaps.** The milestone's original criteria named a Lighthouse a11y
score and a screen recording; neither was measured this chapter — the audit
gates were tsc strict + clean build by standing decision (no UI test suites;
the human tests by hand). Karaoke word-timing and the OGG player in Sessions
remain unbuilt; call log v3 verbs arrive with ms-15.
