# ms-15 — the supervisor: authority is a signature, and the model is the last skeptic

**What we set out to do.** A supervisor opens a live call unseen, listens,
whispers to the agent, takes the line, and transfers — every verb logged with
`seq` in the caller's own event log.

**What shipped.** All of it, on our self-hosted box, with one honest asterisk
(below). `/supervisor` lists live calls; a click mints a `listen` ticket and
streams the call's audio and transcript; the desk whispers, takes the line,
releases it back, and fires a cold transfer whose failure is a rendered
outcome, never a silent hang.

## The security model — one idea carried through every verb

**Authority is the signed token, never a message.** Each capability is its own
grant row minted by `mint_supervisor` — `listen` (hidden, subscribe-only),
`whisper` (hidden, mute, data channel), `takeover` (a real microphone) — with
identity `sup:<uid>`, a signed `{role, cap}` attribute, and a 15-minute TTL.
Every verb, on both roads (browser RPC and control-plane packet), ends at one
gate: `is_supervisor(identity)`, where the identity is the SFU-attested one.
Nothing in any payload can claim supervisorhood. The same human keeps the same
identity across capabilities on purpose: LiveKit admits one connection per
identity, so escalating listen→takeover upgrades the participant instead of
seating a second ghost.

## Learned the hard way — each one measured, none guessed

- **`MoveParticipant` is Cloud-only.** Probed against our own server: "twirp
  error: not implemented". So the official WarmTransferTask is unusable
  self-hosted and warm transfer is hand-rolled with subscription permissions.
- **A hidden participant is invisible even to the agent** — no
  `participant_connected` fires anywhere client-side, while server-side
  `list_participants` sees it with signed attributes intact. So the audit
  trail could not come from watching the room: the desk asks the SFU who
  really entered, reads the capability off the SIGNED attributes, and
  announces the join on a data topic addressed to the agent alone (a broadcast
  would have told the caller's browser someone joined).
- **There is no `session.pause()` in 1.7.1.** Takeover is
  `interrupt(force=True)` + `StopResponse` on every turn while muted — ears
  stay on by default so the human's interval lands in the history for
  `release` to read back.
- **The SDK fires no unsubscribe on a server-side revocation** — the stream
  just goes quiet. An event-watching probe "proved" isolation broken while the
  SFU log said `revoking`; counting audio frames proved both isolation
  mechanisms work, with a ~220 ms tail per stream (recorded, not hidden).
  `scripts/isolation_probe.py` keeps the correct instrument runnable.
- **The whisper's last skeptic is the model itself.** The steer golden caught
  it: on Haiku, a note fails to bend the next line through every delivery —
  system-role (the anthropic plugin relocates all system messages to the top
  block, which would also bust the prompt cache), user-role (delivered in
  position, verified with an `llm_node` spy, still ignored), and
  `generate_reply(instructions=…)`. Our few-shot-anchored prompts win.
  The plumbing is correct and gated; the persuasion is an open card
  (tk-bc0122) with candidate deliveries to measure. The golden that ships
  pins what IS true today: an unverified steer changes nothing and leaks
  nothing, through the real model path.

## Transfer

Cold is a real SIP REFER (`TransferSIPParticipant`) whose every failure comes
back as an `Outcome` with a SIP status — `ok=False` always means the caller is
still on the line, and the agent is told the reason before it speaks. Warm is
implemented end-to-end (hold → isolate → dial → brief → bridge) and refuses at
the door naming `SIP_OUTBOUND_TRUNK_ID`: dialling out needs a Twilio
Termination trunk this deployment deliberately does not have yet — provisioning
it is the human's call, and the Twilio toggles are documented in
`infra/box/README.md` without having touched the account (fraud lessons hold).

## Compliance stance

Listening is silent by design for the DEMO; all-party consent disclosure is a
per-tenant policy decision the audit log already supports (every
`supervisor.*` event is in the caller's own append-only log with `seq` — the
substrate for "this call may be monitored" is there, the announcement is a
greeting-level choice).
