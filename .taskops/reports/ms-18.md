# ms-18 — reserva de cita: the platform's last missing verb, and the board that proves it

**Where this chapter came from.** The ABAI test's use-case list names "Reserva
de cita" and the platform only moved or cancelled existing ones — a caller
with no appointment hit a wall. One afternoon: the missing verb, a board of
business outcomes, and a measurement artefact removed.

## The NewBooking seam — a stage, not a branch

The tempting fix was a branch inside ChooseSlot; the right one was a new
stage, and the argument is worth keeping: ChooseSlot's contract says "the
appointment exists" in four places, and the consent metric watches an
(irreversible, asking) pair — one stage with two irreversible doors makes that
pair ambiguous. Identify grew a deliberate second exit
(`start_new_booking`) that a merely-failed lookup does NOT take: a misheard
surname must never become a duplicate cita. The usual cost of a second stage —
duplicated prompt prose — was paid once and refunded: the shared agenda
paragraphs moved to `prompts/reception.py` **byte-identical**, so no existing
golden moved because of the refactor.

## What the new goldens caught

- **The Sunday catch.** Haiku answered "los domingos cerramos" off the
  opening-hours sheet **without consulting the agenda** — the Thursday lesson
  failing on the one day the model thinks it already knows. One sentence in
  the shared block fixed both stages at once: Tool Correctness 14/16 → 17/17.
- **A tone judge asked to adjudicate a fact will.** A golden whose
  `expected_behaviour` mentioned the fact invited the GEval to score it — a
  correct reply got 0.20. Reworded so the fact stays with `grounded_facts_dag`
  and the tone judge judges tone.
- **consent_graph now watches both irreversible doors.** Two per-errand
  metrics would have scored every new-booking call 1.0 without reading a
  thing; the shared graph scores 0.0 where the old shape scored a vacuous 1.0,
  pinned by test. Consent ring: **8/8 at 1.0 on both models.**

## The board — transactions, not conversations

`GET /outcomes` reads ONLY the append-only log: a transaction is one
irreversible `tool.call`, its `confirm.granted` is the caller's yes (paired
one-to-one, so a second write on one yes reads unconfirmed), and the row's
text is the PII-filtered `result_summary` already in the log — never
re-rendered. No new table: the log is the table, `days` bounds the walk, and
at volume the answer is a materialised view over these same events, never a
counter the executor writes. Refusals are not rows — the guard stopped them,
nothing happened to the business. The generic-by-construction criterion is
pinned twice, the second time brutally: a test reads `core/outcomes.py`'s own
source and fails if any tool name appears in it. And an honest note: the box's
own store held ZERO completed irreversible calls, so the demo rows were
generated through the real executor + guard + mask — evidence, not forgery.

## The artefact that was hiding a defect

`expected_tools: []` meant "no tools" when the contract meant "none of the
business's tools" — the platform clock failed correct turns. The fix is a
declared marker (`ToolSpec.infrastructure`), never a name list, filtered only
in the case ToolCorrectness reads (grounding still sees every output). The
re-run closed the clinic's clock divergence on gpt (15/17 → 16/17) and
levelled tienda's tools at 10/11 on both models — and unmasked the truth: the
second "clock divergence" was a **real gpt defect** («quería una cita con el
dermatólogo» → `find_availability` with no day named), now documented as its
own finding instead of laundered by the artefact.

**Where the model matrix stands after this chapter:** hard policies 100% on
both models in the clinic; consent 8/8 both; no tool-correctness divergences
left that are ours; the remaining reds are model character (GEval line style)
and one named gpt prompt defect — all documented, no golden softened.
