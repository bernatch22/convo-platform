# ms-17 — the operator hears and sees: recordings, orientation, datasets

**Where this chapter came from.** Within an hour of ring 4 going live, the
human hit three walls in a row: a failed eval call could not be re-heard, the
Pipeline screen would not say which project it was configuring, and there was
no way to see WHAT the evals actually ask without opening the repo. One
afternoon, three cards, all three walls down.

## The recorder that was never broken

The best finding of the chapter reframes its own card: livekit-agents 1.7.1
**already records every job** — a `RecorderIO` armed around the session's
audio, one `put_nowait` per frame, resampling and Opus encode in a daemon
thread. The "no added latency" rule is satisfied by a line you can point at.
What was wrong was the destination: outside console mode, the framework aims
the recorder at a `TemporaryDirectory` and deletes it at cleanup. **Every real
call recorded perfectly and then threw the file away.**

The fix redirects the destination during the call (a shutdown-callback copy
was considered and rejected: SIGKILL loses everything), keyed by session id,
git-ignored, with the pointer riding `audio.start` in the append-only log.
`GET /sessions/{id}/recording` serves it; SessionDetail plays it; a project
can opt out like scoring. Two flags stated instead of buried: a supervisor
takeover is inaudible to this tap (RoomIO links one participant — egress's one
real advantage, a named follow-up), and the route's auth is a real bolt
(`RECORDINGS_TOKEN`) on an API that today has none anywhere — the README says
what is and is not protected instead of implying a security it does not have.

## The URL carries the whole truth

The sidebar confusion had a root cause, not a styling problem: sections were
tenant-scoped routes, so the project link lost its active state the moment you
left Talk, and Pipeline guessed its project from a query string. Sections now
hang off the project (`/t/<tenant>/<project>/sessions|pipeline`), the rail
highlights tenant, project AND section derived purely from the pathname, and
legacy URLs redirect — a session bookmark resolves by asking the session which
project recorded it. The accepted trade: Sessions is per-project now; a
tenant-wide roll-up is its own card if anyone misses it.

## The datasets on screen, without breaking isolation

`GET /evals/goldens/{tenant}/{project}` reads the three eval files off disk
and the Datasets view renders every golden as a readable card — the caller's
line, the expected behaviour, the hard policies as chips — grouped by the same
suite name the runs carry. The decision that keeps it honest: the suite→file
join reads the pytest target as **text** and searches it for the dataset's
filename — never imported, never executed, so the core-never-imports-tenants
invariant holds even here. Counts are computed from the files and pinned by
tests; the persona simulators, which are code and not JSON, answer
`kind: "code"` naming their file instead of showing a false zero.

## A testing lesson worth its sentence

A traversal test flipped 404→200 the moment `ui/dist` existed, because the SPA
catch-all answers decoded paths. Nothing leaked — but a test whose verdict
depends on whether the UI is built is a bad test. It asserts the invariant now
(no `audio/ogg` ever comes back), not the status code.

**Verify it live:** call or open a web session, then Sessions → the row wears
`♪` → press play. Datasets: Evals → Datasets. Orientation: go anywhere and
look at the rail.

Read the code: `nvim -p core/recordings.py ui/src/lib/nav.ts
core/evals/goldens.py ui/src/components/Datasets.tsx`
